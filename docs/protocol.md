# 目录协议 v1

## 路径与职责

| 路径 | 用途 | 加载时机 |
| --- | --- | --- |
| `AGENTS.md` | 项目公共规则及角色路由 | 开始任务 |
| `.AGENTS/_shared/CONTEXT.md` | 跨角色已确认的事实 | 开始任务 |
| `.AGENTS/<role>/AGENTS.md` | 角色目标、职责边界、交接对象 | 选择或切换角色 |
| `.AGENTS/<role>/memory/MEMORY.md` | 当前事实摘要及记录索引 | 选择或切换角色 |
| `.AGENTS/<role>/memory/records/*.md` | 决策、经验和未解决问题 | 相关任务 |
| `.AGENTS/<role>/skills/<skill>/SKILL.md` | 可复用方法与适用条件 | 技能匹配时 |
| `.AGENTS/<role>/local/` | 不提交的临时工作资料 | 当前实例自行管理 |

角色和技能名为 1–63 个小写字母、数字、连字符，首尾为字母或数字；排除 Windows 保留设备名（如 `con`、`nul`、`com1`）。`_shared` 仅承载共享上下文，不视为角色。大小写固定，便于跨平台协作。

## Memory：知道什么

`MEMORY.md` 是简短的当前摘要，不是完整会话日志。详细记录使用唯一文件名，例如 `2026-09-21-task-142-parser.md`，避免多个实例修改同一记录。每条记录建议包含：

```markdown
# 决策或经验标题

- Date: YYYY-MM-DD
- Owner: developer / task-142
- Status: active
- Scope: 适用模块或条件
- Evidence: 提交哈希、代码路径、测试结果或可访问的来源
- Review after: 相关接口变更时，或 YYYY-MM-DD

## Finding
已确认的事实；将假设与结论明确区分。

## Consequence
今后什么情况下该使用这一信息。
```

状态建议使用 `active`、`superseded`、`archived`。新记录取代旧记录时，注明替代关系并更新摘要，保留追溯线索。遇到与当前代码冲突的记忆先核验，确认后修正。长期无用的记录移出当前摘要，不要让历史内容无限增长。日期、证据和状态是维护约定，CLI 不判定其真实性。

## Skill：怎么做

技能由一个目录和 `SKILL.md` 组成。文件使用 YAML frontmatter，至少包含 `name` 和 `description`；名称与目录一致。描述应表达具体能力和使用条件，正文给出必要流程与验证方式。

```markdown
---
name: api-change
description: 修改 API 契约时核查调用方、兼容性和迁移验证。
---

# API change

确认接口使用方与现有契约，再确定兼容策略。针对受影响调用路径验证变更，记录需要的迁移步骤。
```

需要时添加 `scripts/`、`references/`、`assets/`，从正文链接到具体资源；不要默认将它们全部加入上下文。CLI 只列出技能或输出选中 `SKILL.md`，不加载资源、不执行脚本。

CLI 的元数据检查仅支持本仓库使用的非空单行 `name` 和 `description` 字段；这是一项工具限制，不是完整技能标准。若需要更复杂的 YAML，应在使用客户端的技能工具中另外验证。

## 加载和优先级

先读公共入口、共享上下文、角色职责和摘要，再按任务选技能与记录。加载顺序用于节省上下文，不建立新的指令优先级。客户端原生规则和用户任务始终按其原有机制生效。角色约定不能授权任务之外的操作，历史记录不能覆盖现行规则。

CLI `context` 在输出中标注相对路径，先组装这四个入口文件，然后列出技能和记录；只有显式给出的 `--skill` 和 `--record` 才加入正文。`--record` 接收 records 目录内直接子文件的文件名，不接受路径。符号链接与 Windows junction 被 CLI 拒绝，以避免读取或写入指定项目之外的内容；普通文档阅读者仍应自行辨别来源。

## 多 agent 协作

- 用角色划分长期知识，用任务标识区分运行实例，不把进程名当作角色名。
- 两个 developer 并行时，各自使用独立 worktree 或明确的文件分工；新建不同的记录文件。
- 交接说明完成内容、证据、剩余问题和涉及文件。接收角色核验后更新自己的摘要。
- 共同事实先协调再写入 `_shared/CONTEXT.md`；不要在每个角色目录复制同一份事实。
- Git 合并解决文本冲突，评审解决语义冲突。本协议没有锁或自动仲裁器。

## 从单一 AGENTS.md 迁移

1. 保留公共规则、命令和路径范围约定。
2. 将职责说明移入相应 `AGENTS.md`。
3. 将重复工作方法提炼为技能；历史结论提炼成带证据的记忆。
4. 在原入口合并角色读取说明，使用 `check` 检查必要结构。
5. 用一次实际任务验证客户端确实读取了所选角色文件。
